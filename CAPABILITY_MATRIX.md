# Capability matrix

| Capability | Normal computer with Codex CLI | Codex Mobile target | Honest limitation |
| --- | --- | --- | --- |
| Real Codex experience | Native interactive TUI | Same real TUI in persistent remote PTY | Mobile rendering/input passes through network and SwiftTerm |
| Multiline input and attachments | Local terminal/editor tooling | Native target-labeled composer with encrypted drafts/history, system dictation, Photos/files, and explicit Send into the real TUI | Attachments are bounded temporary workspace files, readable by code in that workspace, expire after 30 minutes, and are unavailable offline |
| ChatGPT entitlement | Browser/device login | Headless device-code login | Device auth is currently beta; owner must complete it |
| Connection lifecycle | Local account/tool controls | Owner-scoped aggregate GitHub and per-workspace Codex status; confirmation-gated local GitHub and Codex disconnect | GitHub disconnect revokes only this server's local minting authority, not the external App installation. Codex disconnect removes that workspace's app-owned sessions/auth but does not revoke the upstream ChatGPT account; reconnect requires a fresh live device login |
| Shell/process persistence | Depends on local terminal/tmux | Server-side tmux survives app/network loss | Host reboot stops processes; filesystem persists |
| Files/Git | Full local CLI/editor | Repository CLI plus focused native file/Git UI; authenticated bootstrap and native remote operations use ephemeral in-process `go-git`, while production Linux file access uses fd-relative no-follow access and exact displaced-content ETag save CAS | The service does not inject GitHub credentials into arbitrary CLI Git. Private authenticated remote operations use the trusted native/bootstrap path; after an uncertain save error the app must fresh-read before retry, and portable non-Linux development cannot guarantee final-window CAS against an external writer |
| Local recovery | Manual Git/filesystem tools | Verified local checkpoints, file restore, v2 recorded-delta workspace restore, and checkpoint-backed tracked-path discard | Delta restore is not a full volume backup; local checkpoints are lost with total VPS/storage loss |
| Parallel sessions | Local machine capacity | Up to 10 equal-share workspaces with continuous start reservation, exact-running provider barriers, crash-conservative quota high-water, scan-driven convergence, immutable 8–16 GiB XFS project-quota volumes, fixed PID ceiling, verified-device BPS/IOPS maxima, and bounded EnvBuilder rootfs | Finite VPS; heavy work slows all sessions, excess starts queue, unresolved provider state can conservatively block starts or delay full share restoration, and kernel quota/cgroup enforcement still needs the target-host actual-template-container proof |
| Inactivity/retention | Manual local process management | Process/port-aware idle suspension with global/per-workspace timeout and 7/30/90-day or forever retention; stop/delete persist a retryable state and drain terminal/preview authority before confirmed provider completion | Live timing and provider/tmux/tunnel cleanup still require the target Linux Coder deployment |
| Isolation | User/OS dependent | Separate user-namespaced non-privileged containers/volumes/networks/worktrees; no runtime socket or privileged Coder API/provisioner token in Coder workspaces | Shared host kernel, not VM-grade multi-tenant isolation. The private quota-engine socket is root-equivalent authority held by the provisioner. Each workspace necessarily has a scoped `api_key_scope=no_user_data` Coder agent token that same-authority repository code may observe/use; live hostile proof must show it grants no privileged/cross-workspace authority |
| Devcontainers | Local Docker/compatible runtime | Plain authenticated bootstrap followed by a durable, non-expiring, reconciled setup review and approval-gated Coder/EnvBuilder restart with the persisted standard config directory | Compose, privileged/root, host-mount, added-capability, host-init, run-argument, and nested-Docker configurations use only the explicit safe plain fallback |
| Docker workloads | Local Docker | Optional approval-gated private rootless nested engine | Off by default; kernel compatibility must be proven |
| Network | Local policy | Every workspace has a private bridge and an immutable per-workspace Coder relay; only the relay joins the fixed control uplink, while Balanced/Full Access add a separate per-workspace egress bridge after a suspended state transition | Safe Mode is designed to retain only Coder agent control, not general egress. Rootful-Podman bridge/firewall behavior, agent registration and denial of every other host route remain a target-Ubuntu gate |
| Previews | Local browser/ports | Authenticated isolated HTTP/WS routes with device-bound grants and device/session/workspace revocation | Requires stable domain/DNS/TLS; hostile content remains risky |
| Offline | Local files and commands | Encrypted recent read-only cache plus encrypted unsent composer drafts/history; authoritative active-grant output is redacted before replay/cache and the native cache adds conservative token heuristics | No offline sends, attachment persistence, edits, or commands; received content is explicitly stale, and unrelated sensitive output cannot be detected perfectly |
| Secrets | Local environment/keychain | Encrypted server vault with explicit grants and live authoritative tmpfs grant/revoke sync for future process launches; creation-time environment/prompt values must all persist encrypted before provisioning becomes eligible | Granted repository code can read/exfiltrate runtime secrets; processes already running at revoke keep their inherited environment until closed; an interrupted creation-time private-input write requires workspace deletion/recreation and value re-entry |
| Notifications | Terminal/desktop notifications | Generic APNs + authenticated in-app review | Structured detail depends on supported Codex events; never inferred from ANSI screen |
| CI validation | Local commands | Public pull requests and `main` run the portable suite on standard GitHub-hosted Linux and the native suite on standard hosted macOS | Jobs require public visibility plus the explicit CI variable, use read-only permissions and no secrets, and larger/paid or persistent self-hosted runners are prohibited |
| Release image integrity | Ad hoc local builds | Three commit-tagged local images are scanned by exact ID with checksum-pinned free Syft/Trivy, one frozen database snapshot, profile-3/schema-2 14-field exact dispositions, per-image duplicate-sensitive non-forbidden-license baselines, and a root-only receipt/report tree bound into immutable manifest schema 2 before promotion | A WSL build/scan proves the candidate images only; production activation, AppArmor/XFS/runtime enforcement, and later rebuilt IDs still require their own target-host gate |
| iOS/macOS tooling | Available on a Mac | Xcode 26.6 project generation and iPhone simulator tests run remotely on GitHub-hosted macOS | Physical iPhone/iPad behavior, signing, APNs production delivery, archive, and TestFlight still require owner-controlled Apple credentials and device acceptance |
| Hardware/GUI apps | Local machine dependent | Linux CLI/server tools only | No arbitrary desktop GUI or device passthrough |
| Availability | Local machine lifetime | Single VPS + included daily whole-server backup | No HA/second server; up to ~24h server-loss recovery point. The backup includes encrypted data and the host master key, so it improves availability but is not cryptographically separated from provider/full-backup compromise |
| Billing | Existing local resources | Exactly one fixed monthly VPS | Capacity never auto-scales or purchases overages |

Core product paths that depend on Apple signing, a real GitHub App, an owner domain, APNs, ChatGPT device login, or a purchased VPS cannot be truthfully marked end-to-end verified until the owner authorizes those external actions.
